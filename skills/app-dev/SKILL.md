# App Dev

## Purpose

Implement the planned app changes and describe what the change actually contains.
Development produces implementation evidence, not workflow decisions.

## How to think about this phase

- Treat the record as an account of the change, not of the intent. Use exact local file refs when identifying changed files.
- Treat approval as bound to the exact change digest; a later edit changes the object being approved.
- Connect findings and corrections with exact evidence so the record explains what changed and why.
- Make the final artifact an honest account of what changed, what was found, and what remains true.

## Orchestrator ownership

The orchestrator's workflow owns sequencing, gates, and recording. This skill does not mandate task order, review or correction cycles, approval timing, delegation, or phase transitions.
